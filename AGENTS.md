# AGENTS.md

## Repo Shape
- This repo is a script-driven research prototype, not a packaged library. The main entrypoint is now `main.py`, which dispatches into `pipeline.py`.
- The legacy scripts `train_bd_intracl.py`, `train_davis_intracl.py`, `protfeature.py`, and `build_graph.py` are thin wrappers around the unified pipeline.
- `model.py` implements the paper's core model: KPGT drug embeddings + ESM residue embeddings + GCN + `GraphMultisetTransformer` pooling + bilinear classifier.

## Environment
- Separate the local coding environment from the actual training runtime. OpenCode sessions here run in a local `uv` setup on Python 3.14 for editing only.
- Trust checked-in runtime config over the local coding environment and over the README badge: `.python-version` is `3.11`, and both `pyproject.toml` and `uv.lock` require `>=3.11`.
- For the ML stack, use `environment.yml`; it is the only file that declares the actual training dependencies (`torch`, `torch-geometric`, `rdkit`, `esm`, `tmscoring`, etc.).
- `pyproject.toml` is not enough to run training; it only lists lightweight local tooling (`jupyter`, `markitdown[pdf]`).
- Real model runs are expected to happen on a GPU-enabled RunPod VM accessed over SSH and configured from `environment.yml`, not in the local OpenCode `uv` environment.
- The Conda env name in `environment.yml` is `drug2`, so `conda activate drug2` matches the checked-in config.
- The checked-in bootstrap notebook is `GSDTI.ipynb`; it is legacy Colab-oriented setup guidance, but the current runtime target is a RunPod SSH VM with the same split-env shape: `drug2` for GS-DTI/ESM/OpenFold and a separate `kpgt` env for KPGT+DGL.
- The `kpgt` micromamba env in `GSDTI.ipynb` uses `pytorch=1.13.1`, `pytorch-cuda=11.7`, `dgl-cuda11.7=0.9.1post1`, plus `mkl=2024.0` and `intel-openmp` from `defaults`; this avoids both CPU-only PyTorch solves and the `libtorch_cpu.so: undefined symbol: iJIT_NotifyEvent` import failure seen with the older KPGT stack.
- The `drug2` micromamba env in `GSDTI.ipynb` needs `omegaconf` in addition to `fair-esm`; `esm.pretrained.esmfold_v1()` imports it at runtime when generating ESMFold structures.
- The `drug2` OpenFold/ESMFold stack also needs `dllogger`; `GSDTI.ipynb` installs it from `git+https://github.com/NVIDIA/dllogger.git` alongside the other `fair-esm` extras.
- The OpenFold install in `GSDTI.ipynb` must match the upstream ESM recommendation: install `openfold` from commit `4b41059694619831a7db195b7e0988fc4ff3a307`, or ESMFold can fail at load time with missing structure-module keys.
- On current PyTorch 2.4-style stacks, that OpenFold commit still needs a tiny source patch before install: replace `-std=c++14` with `-std=c++17` in `setup.py`, or the CUDA extension build fails with `C++17 or later compatible compiler is required to use PyTorch`.
- Some OpenFold combinations can still fail at `openfold.model.primitives` with `AttributeError: module 'importlib' has no attribute 'util'`; `GSDTI.ipynb` applies a tiny source patch to `openfold/model/primitives.py` so `importlib.util` is imported explicitly before install.
- That OpenFold commit also expects an older `pytorch_lightning` import path for `seed_everything`; `GSDTI.ipynb` patches `openfold/utils/seed.py` to import it from `lightning_fabric.utilities.seed` for compatibility with newer runtime envs.

## Data And Entry Points
- The checked-in sample dataset is under `data/BindingDB/`, with `drugs/drugs.csv`, `targets/targets.csv`, and `df_less1000.csv`.
- `main.py` supports `prepare`, `train`, `infer`, `run`, `batch-predict`, and `repair-labels` subcommands. Use it for both the checked-in BindingDB sample and custom datasets.
- Custom datasets can be ingested from `.csv` or `.parquet` with user-specified `smiles`, `sequence`, and `activity` columns. The pipeline rewrites them into the repo's canonical `Drug_ID/Drug/Target_ID/Target/Y/Label/Target_Length` layout under `data/<dataset>/`.
- Binary activity columns containing only `0` and `1` are treated as already-labeled data: canonical `Y` preserves the numeric activity and `Label` copies it exactly instead of applying the numeric threshold.
- `main.py repair-labels` repairs only `Y` and `Label` in an already-prepared `df_less1000.csv` by matching the original CSV/Parquet rows to surviving canonical interactions. It leaves all expensive KPGT, ESM-2, ESMFold, graph, and similarity artifacts untouched.
- The unified pipeline can also place canonical datasets and derived artifacts under a custom root passed via `--artifacts-dir` instead of the repo-local `data/` directory.
- The unified pipeline creates the expected derived artifacts under `<artifacts-dir>/<dataset>/drugs` and `<artifacts-dir>/<dataset>/targets`: `kpgt_base.npz`, `prot_rep.pkl`, target graph `.pt` files, `drug_simmatrix.npz`, and `target_simmatrix.npz`.
- If KPGT cannot build a graph for a substance, the streaming extractor records it in `<artifacts-dir>/<dataset>/excluded.csv`, omits it from `kpgt_base.npz`, and `pipeline.py` removes that `Drug_ID` from `drugs.csv` and every interaction row before subsequent preparation stages run. Preparation failures now abort by default; pass `--drop-failed-entities` (the `batch-predict` default) to record and drop them instead.

## Append-Mode Preparation
- `prepare` is append-first. If `<artifacts-dir>/<dataset>` already has `drugs/drugs.csv` and `targets/targets.csv`, a rerun keeps every existing `Drug_ID` / `Target_ID` and its derived artifacts, mints ids only for genuinely new SMILES / sequences, and appends them to the *end* of the canonical tables. Interaction rows whose `(Drug_ID, Target_ID)` pair already exists are skipped as duplicates.
- Pass `--rebuild` (or `--force`) to get the old behaviour of rewriting the canonical tables from `--input`.
- Every derived artifact is positionally aligned with its canonical table: `kpgt_base.npz` row *i* is `drugs.csv` row *i*, `prot_rep.pkl` entry *i* and `target_simmatrix.npz` index *i* are `targets.csv` row *i*. Append mode only ever extends an artifact's tail, which is what preserves that.
- `<artifacts-dir>/<dataset>/artifact_manifest.json` records, per artifact, how many leading table rows it covers plus a hash of exactly which ids those were. A table that changed underneath an artifact fails loud and tells you to rerun with `--force` instead of silently scoring the wrong drug against the wrong protein. Datasets prepared before this file existed are trusted once and then get a manifest written.
- Every preparation stage is now a sync rather than an all-or-nothing generate: KPGT streams only the appended drugs through `scripts/kpgt_streaming_extract.py` (into `drugs/kpgt_pending.*`, discarded once merged), ESM-2 embeds only the appended targets, and `sim_matrix.compute_and_extend_tm_score_matrix` computes only the TM-score pairs that involve a newly appended target and copies the existing block verbatim.
- The TM-score extension checkpoints after every appended target into `target_simmatrix.tm.tmp.npy` plus `target_simmatrix.tm_resume.json`, so an interrupted O(n^2) job resumes at the last completed row. `prot_rep.pkl` is rewritten atomically every `--esm-checkpoint-seconds` (default 600) for the same reason.
- `_drop_dataset_entities()` is the single path for removing a failed substance or target. It compacts whichever aligned artifacts already covered the dropped row, so the old `resolve_compaction_indices` remapping in `_restrict_to_existing_esmfold_targets` is gone; that function now only validates the *pending* target tail against existing PDBs.
- `--skip-similarity` skips `drug_simmatrix.npz` and `target_simmatrix.npz` entirely. They are training-only inputs (`utils.custom_collate_fn`); `infer` and `batch-predict` never read them. A dataset prepared with the flag is not train-ready until `prepare` is rerun without it.
- Appending only entities (no interactions) is a valid state: `df_less1000.csv` may be present but empty, which is what a `batch-predict`-only dataset looks like.

## Batch Prediction
- `main.py batch-predict --dataset <name> --checkpoint <best.pt> --substances-json <f> --targets-json <f>` does the whole thing in one command: append-prepare whatever is new, then score the full substances x targets cartesian product into streamed Parquet chunks.
- Entity lists come from `--substances-json` / `--targets-json` (flat string arrays) or `--substances-parquet` / `--targets-parquet`. `scripts/prepare_batch_tables.py` converts JSON arrays into the Parquet form. A Parquet table carrying its own `substance_id` / `target_id` column must be keyed 0..N-1; the output chunks are written against those ids.
- Output chunks are `part-NNNNN.parquet` under `<artifacts-dir>/batch_predict/<slug>/` (or `--output-dir`), with the minimum-size schema from `scripts/batch_predict_utils.py`: int32 `substance_id` / `target_id` DELTA_BINARY_PACKED, int8 dictionary-encoded `predicted_label`, and float16 `probability_active` only (`probability_inactive` is always `1 - p`). Use `--probability-dtype float32` for full precision.
- `progress.json` in the output directory records the next unscored pair and chunk index; a rerun resumes there. A chunk file that exists on disk but was never recorded is detected and skipped. `--no-resume` restarts. The progress fingerprint covers the entity lists, checkpoint, chunk size, probability dtype, and pair order, so a mismatched rerun refuses rather than interleaving results.
- Sidecars go under `<output-dir>/meta/`, not next to the chunks, so the chunk directory holds only same-schema `part-*.parquet` files: `meta/substance_map.parquet` and `meta/target_map.parquet` map the integer ids back to canonical `Drug_ID` / `Target_ID` and the raw SMILES / sequence, and `meta/unscored_entities.json` lists inputs dropped during preparation. `progress.json` stays at the top level to match DCGAT-DTI, so read chunks with an explicit `part-*.parquet` glob rather than pointing a Parquet dataset at the directory.
- `--pair-order` defaults to `target-major` because the protein side of a pair is a serialized PyG graph on disk while the drug side is one row of an in-memory matrix; target-major deserializes each graph once. `--graph-cache-size` (default 256) bounds the LRU graph cache. Only switch to `substance-major` if the whole graph set fits in the cache.
- `--pair-batch-size` defaults to 64, not DCGAT-DTI's 1024, because each pair in a forward pass carries a full residues x 1280 protein graph. A CUDA OOM halves the batch and retries rather than failing the run.
- `batch-predict` defaults to `--skip-similarity` and `--drop-failed-entities`; pass `--no-skip-similarity` / `--no-drop-failed-entities` to override. `--skip-prepare` goes straight to scoring and assumes every substance and target is already prepared.
- There are no artifact fallbacks anymore. Missing `kpgt_base.npz`, `prot_rep.pkl`, ESMFold `.pdb` files, graph `.pt` files, or similarity matrices must be generated with the real KPGT / ESM-2 / ESMFold flow or preparation fails.
- True KPGT generation requires an external KPGT checkout and model path passed through the CLI, since this repo does not vendor KPGT itself.
- When the runtime uses a separate KPGT environment, pass `--kpgt-python` so preprocessing and feature extraction run with that interpreter rather than with the main GS-DTI runtime.
- `pipeline.py` invokes `scripts/kpgt_streaming_extract.py` with the KPGT repo root injected into `PYTHONPATH`, because upstream KPGT modules import as `from src...` and fail if launched without the repo root on the Python path.
- `train_bd_intracl.py` now prepares `BindingDB` and then calls the unified trainer with `epochs=1`.
- `train_davis_intracl.py` now expects a dataset folder named `data/DAVIS_processed/` and routes both training and evaluation through the unified trainer.

## Path Gotchas
- Centralize dataset paths through `dataset_config.py`; do not reintroduce hard-coded `/GS-DTI/...` or dataset-specific relative paths in individual scripts.
- `dataset_config.get_dataset_paths()` normalizes dataset directory lookup across case variants such as `BindingDB` versus `bindingdb`, and also accepts a custom artifacts root.
- Results are written under the repo-local `results/` directory by default, or under the CLI `--output-dir` when provided.
- Training checkpoints and run metadata are written under `<artifacts-dir>/training_runs/<dataset>_<hash>/` or `data/training_runs/<dataset>_<hash>/` by default. Each matching run folder contains `params.json`, `last.pt`, and `best.pt`.
- `main.py infer --dataset <prepared-name> --checkpoint <best.pt-or-last.pt>` loads an existing training checkpoint without training or splitting the data, scores every canonical interaction row, and writes `<dataset>_predictions.parquet` under `results/` or `--output-dir`.
- `sim_matrix.py` no longer contains a dataset-specific runnable block; call it through `pipeline.py` / `main.py` or import its helpers.

## Runtime Constraints
- The dataset classes now keep tensors on CPU until the training loop moves them onto `device`, so CPU execution is no longer blocked by `.cuda()` calls inside `__getitem__`.
- Most scripts load large artifacts at import/startup time (`np.load`, `pd.read_csv`, `torch.load`), so missing files fail immediately before any training loop starts.
- `pipeline.py` configures the shared `argparse` help formatter with `width=180` for the top-level parser and its `prepare`/`train`/`infer`/`run`/`batch-predict` subcommands, so CLI help text wraps much later than the Python default.
- `prot_rep.pkl` is a single pickled list, so append mode has to load the whole existing file before extending it. That is the format's memory ceiling for very large target sets; do not "fix" it by switching to multi-frame pickles without updating every reader.
- `prepare` now performs true preprocessing only: ESM-2 residue embeddings are generated in-process, ESMFold `.pdb` files are generated in-process, and KPGT features are generated by shelling out to a repo-local streaming extractor that imports an external KPGT checkout. This is GPU-heavy and, in the current RunPod SSH flow, runs with `drug2` for GS-DTI/ESM/OpenFold and a separate `kpgt` env for KPGT+DGL.
- `prepare` now shows `tqdm` progress bars for the overall stage flow and for per-target ESM-2 embedding generation, ESMFold `.pdb` generation, and protein graph building. Existing completed artifacts are skipped unless `--force` is used, while the KPGT streaming extractor can resume its own interrupted temp output even when the parent `prepare` command is rerun with `--force`.
- During ESMFold PDB generation, `pipeline.py` sorts pending targets by sequence length before folding, logs each target's `Target_ID`, residue count, and active chunk size, and automatically halves the ESMFold chunk size on CUDA OOM before retrying the same target. If chunk size `1` still OOMs, it raises a fail-loud error naming the target; rerun without `--force` to keep completed `.pdb` files.
- `prepare` and `run` accept `--skip-esmfold` to avoid generating additional structures. Existing `targets/esmfold/<Target_ID>.pdb` files become the source of truth: the pipeline removes targets with missing, unreadable, or sequence-mismatched PDBs; records each rejected target in `excluded.csv`; and compacts the canonical interaction, drug, and target tables plus already-generated aligned features and similarity matrices before continuing.
- When `--input --skip-esmfold` regenerates full canonical tables over artifacts compacted by an earlier skip run, the filter recognizes both the full-table and legacy existing-PDB layouts and remaps artifacts by `Target_ID` / `Drug_ID` before applying stricter sequence validation.
- `pipeline.py` writes `tqdm` bars to `stdout`, forces them enabled by default, and keeps the per-target bars visible after completion so they still show up in SSH logs or notebook subprocess output.
- `pipeline.py` also reconfigures `stdout` and `stderr` for line-buffered, write-through output at CLI startup so SSH and subprocess runs are more likely to surface live `tqdm` redraws without requiring `python -u`.
- `prepare` also emits periodic plain-text progress lines with `flush=True`, because long SSH or notebook runs can buffer ordinary stdout or lose carriage-return redraws while GPU work is running.
- `prepare` also emits persistent `print()` logs before each stage and when stages are skipped or about to generate artifacts, because remote logs do not always preserve `tqdm` redraws.
- `train` now emits persistent logs for asset loading, split sizes, device selection, dataset/dataloader sizes, epoch starts, validation/test evaluation, checkpoint saves, best-F1 updates, and output writing. Its train/validation/test batch loops also use `tqdm` bars plus periodic plain-text progress lines so long remote runs do not look stuck.
- Training and inference prediction exports are Parquet files with exactly `smiles`, `sequence`, `label`, `probability`, and `real_value`; `probability` is the positive-class probability and `real_value` preserves canonical `Y`.
- Training uses validation-F1 early stopping on plateau with default `--early-stopping-patience 5`; pass `0` to disable. Final validation/test reporting reloads `best.pt`, not the possibly overfit last epoch.
- Training resume is automatic for identical model-affecting start parameters: dataset, optional test dataset, resolved artifacts root, and `TrainingConfig`. Matching reruns load `last.pt` and continue from the next epoch; changed parameters create a different hashed run folder.
- `pipeline.py` applies a small compatibility patch to KPGT's `rdNormalizedDescriptors.py` before preprocessing so SciPy's modern `gibrat` name still satisfies KPGT's legacy `gilbrat` lookup.
- KPGT feature generation does not use upstream KPGT's all-at-once `preprocess_downstream_dataset.py` plus `MoleculeDataset` path anymore, because that path materializes the full graph list, descriptor array, loaded graph cache, and extracted feature list. `scripts/kpgt_streaming_extract.py` processes drugs in chunks, writes features incrementally to `kpgt_base.fps.tmp.npy`, records progress in `kpgt_base.kpgt_resume.json`, and only saves/removes temp state after `kpgt_base.npz` is complete.
- KPGT graph-construction failures are treated as data exclusions, not fatal preprocessing errors. The extractor writes rejected input rows plus `source_row` and `exclusion_reason` to `excluded.csv`; the final `kpgt_base.npz` is compacted to valid drugs only, and the parent pipeline rewrites canonical drug, interaction, and target tables to keep later artifacts aligned.
- When rerunning a custom dataset with `--input`, the raw canonical tables are rewritten before KPGT exclusions are re-applied. `_apply_kpgt_exclusions()` must preserve already completed target-derived artifacts such as `prot_rep.pkl` when the post-exclusion target table is unchanged; only drug-derived artifacts should be invalidated for drug-only changes.
- For interrupted KPGT runs that predate `kpgt_base.kpgt_resume.json`, rerunning the same command can infer the completed prefix from the zero-filled tail of `kpgt_base.fps.tmp.npy` and resume at the last full chunk boundary. If that inference fails, delete the temp `.npy` to restart KPGT from scratch.
- The KPGT streaming controls are `--kpgt-chunk-size` (default `1024`), `--kpgt-preprocess-jobs` (default `4`, workers inside a chunk), and `--kpgt-batch-size` (default `32`, model inference batch size). For RunPod memory growth, reduce chunk size first; reduce jobs only for per-chunk spikes.
- Target TM-score matrix generation is exact but O(n^2) and CPU/file-I/O heavy. `prepare` / `run` expose `--target-similarity-processes` and `--target-similarity-chunksize`; on RunPod, fewer workers than `cpu_count()` plus a larger chunksize can be faster and safer than the default all-worker pool.
- `train_bd_intracl.py` currently trains for `epochs = 1`; `train_davis_intracl.py` uses `epochs = 30`.

## Verification
- There is no checked-in test, lint, or typecheck configuration. Do not invent `pytest`, `ruff`, or `mypy` workflows for this repo.
- The most realistic verification is a focused CLI smoke check such as `python main.py --help` and, in the full Conda runtime from `environment.yml`, `python main.py prepare --dataset BindingDB --kpgt-dir <path> --kpgt-model-path <path>` or `python main.py run --dataset <name> --input <file> --artifacts-dir <path> --output-dir <path> --kpgt-dir <path> --kpgt-model-path <path>`.
- For `batch-predict`, smoke test with a handful of substances and targets first (`--chunk-rows` small enough to produce several chunk files), confirm resume works by interrupting and rerunning, and only then scale up.
